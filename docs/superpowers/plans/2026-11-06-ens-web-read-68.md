# ENS Web Read Layer (#68) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The part of the web app that reads ENS and decides what to believe: resolve an agent's name and records from mainnet at runtime, run the two-way check against Base, detect an owner change, and parse the reputation mirror, all as typed results the UI (#71) only has to draw.

**Architecture:** Pure, dependency-injected modules in `frontend/src/chain/ens/` that import only viem and each other (no `import.meta.env`, no React), so they are unit-tested with stubs in vitest and **also** run against real mainnet and Base Sepolia forks from the `ens/` package. A thin hook and a live-config file wire them to the app's configuration. Nothing in this issue draws UI.

**Tech Stack:** TypeScript 5.9 (frontend `tsconfig.app.json`), viem 2.57, vitest 5, React 19 (hook only). Fork integration tests use the `ens/` harness (node:test, anvil).

**Spec:** `docs/HLD-ens-integration.md` (6.2, 6.3, 7, 8.1, 8.3, 8.4 part 1, E5, E11, O10), GitHub issue #68 (read layer; the UI is #71), ENSIP-25. Reuses the verified resolver ABI and the fork harness from the #66, #67 and #69 plans.

## Rulings this plan makes (the user can overturn each)

- **Result model:** every outcome is a typed value, never an exception for an expected condition. `verification` is `verified` or `failed` with a `reason`; an RPC or fetch failure is a `failed` with reason `read-failed`/`registration-file-unreachable` and a `detail`, so the UI cannot show a tick by accident. `badge` is `"verified"` only when verification is verified **and** the operator state is not `changed`.
- **Operator state (8.4 part 1):** `mergit.operator` (written by the publisher, #69) is compared with `Identity.operatorOf(agentId)` on Base. Different means `changed` and **blocks the tick**; a missing record means `unknown` and does not block the tick (the publisher may not have run yet) but is reported.
- **Name to agent:** this layer takes `{ agentId, label }`. The web app learns the pairs from the API's agent list (#71). `labelForAgent(name)` returns the name only if it is already a valid label and `null` otherwise: it never rewrites a name into a different label, so an agent is never shown under another agent's ENS name.
- **Safety of displayed values:** `agent-endpoint[web]` is returned only if it is an `https` URL (else `null`), so the UI can never be handed a `javascript:` link. `agent-context` is returned as raw text for the UI to render as plain text or sanitised markdown.
- **No hard-coded values:** the resolver and the owner of `mergit.eth` are read from the mainnet registry at runtime. Only contract addresses (Universal Resolver v2, ETH registry, Identity) and the RPC URL (`VITE_ENS_RPC_URL`, default a public mainnet RPC) are configuration.
- **Writers (best effort):** which account last wrote each record is read from the resolver's `TextUpdated` logs inside a bounded block window (public RPCs limit log ranges). Outside the window the answer is `null`, never a guess. It is the last task and can be cut without affecting the rest.
- **Reputation mirror:** a record whose `source` (chain id and contract) is not the configured Base `ReputationAnchor` is treated as malformed.

## Global Constraints

- Work on `main`; no branches or PRs. **Never run git write commands**; print commit commands for the user, with no `Co-Authored-By` trailer.
- **Pushing `frontend/**` triggers the frontend CI and then the deploy** (workflow `frontend.yml`, then `deploy.yml`). Nothing here is imported by a screen yet, so behaviour does not change, but say so when giving the commit commands.
- New files under `frontend/src/chain/ens/` import only `viem` and sibling files, **with explicit `.ts` extensions** (needs `allowImportingTsExtensions` in `tsconfig.app.json`, added in Task 0) so Node can import them from `ens/` tests. Erasable TypeScript only (no enums, namespaces or parameter properties). No `import.meta.env` and no React in these files.
- Follow the frontend's style: colocated `*.test.ts`, user-facing messages as plain sentences, prettier formatting (`npm run format:check`), `npm run lint`, `npm run typecheck`, `npm test` must pass.
- ENS values are display data only and are never imported by routing or run-submission code (E11); a test enforces it.
- Mainnet is read-only. Fork tests use anvil test accounts; RPC URLs come from the environment; tests skip without `ENS_MAINNET_RPC`.
- Contract addresses: Universal Resolver v2 `0x06fdd07f007adac667177b46ab2eb9a75132cfd5`, ETH registry `0xf60aba43e1f7f3dab1186ff03b561401c9df85e2` (mainnet); Identity `0x72eAc041Ee897fF0385022639452fE08Dcd4B7D6` and ReputationAnchor `0xf9DBfF75887361A67269765DA6F8732b233Fda76` (Base Sepolia, chain 84532). `Identity.tokenURI` is not in the frontend's `identityAbi`, so this layer declares the one function it needs.
- ENSIP-25 key: `agent-registration[<ERC-7930 Identity address>][<agentId>]`, value non-empty (`"1"`); ERC-7930 for Identity on 84532 is `0x0001000003014a341472eac041ee897ff0385022639452fe08dcd4b7d6`. Registration file (ERC-8004): `services` has `{ name: "ENS", endpoint: "<label>.mergit.eth" }`, `registrations` has `{ agentId, agentRegistry: "eip155:84532:<identity>" }`.

## Review Focus

1. **A registration file that names a different ENS name or lists another agent id or registry:** `failed`, never `verified`, and the detail names both sides. (Task 4)
2. **Hostile or malformed values:** an `agent-endpoint[web]` that is `javascript:`/`http:`/relative, a `mergit.reputation` that is not JSON, has negative or fractional counts, `__proto__` keys, or comes from another contract, and a registration file that is huge or not an object: none can crash the reader or reach the UI as trusted data. (Tasks 2, 3, 4)
3. **RPC failure at any single read** (ENS text, registry, `tokenURI`, `operatorOf`, the file fetch): a typed failure naming what could not be read, no thrown exception, no tick. (Task 4)
4. **Agent sold on Base:** the result becomes `owner changed` and loses the tick, tested against a real Base fork. (Task 7)
5. **The same label can never resolve to a different agent's data:** `labelForAgent` refuses names that are not already valid labels, and the two-way check ties the id to the name through the registration record. (Tasks 1, 4)
