# ENS Writer Service (#69) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the service that writes to ENS on Mergit's behalf: the reputation mirror (`mergit.reputation`) from `ReputationAnchor` events, the operator record (`mergit.operator`) that makes an agent transfer visible, and operator-requested edits to `agent-context` and `agent-endpoint[web]` after an ownership check (decision O9, option (a)).

**Architecture:** Pure, tested functions (outcome fold, record builder, edit-request verification) plus one publish pass that reads Base Sepolia, compares with what ENS already holds, and sends **one batched transaction** only if something changed (R14). A thin Node service exposes `POST /edit` and runs the publish pass on a timer. Runs in `ens/` (TypeScript, reusing the #66/#67 harness). Two separate keys: publisher and editor.

**Tech Stack:** Node 24 (type-stripping, erasable syntax only), viem 2.57, `node:test`, anvil forks of mainnet (ENS) and Base Sepolia.

**Spec:** `docs/HLD-ens-integration.md` (E5, E6, sections 6.3, 7, 7.1 L1/L2, 8.2, 8.4, 9.1, R13, R14), GitHub issue #69. Builds on `docs/superpowers/plans/2026-11-06-ens-gate-m0-m1.md` and `docs/superpowers/plans/2026-11-06-ens-identity-67.md`.

## Rulings this plan makes (the user can overturn each)

- **O6:** TypeScript in `ens/`, not Rust beside the gateway. It reuses the verified resolver ABI, the fork harness and viem, and ships without touching the Rust services.
- **O7:** the two keys are read from environment variables (`ENS_PUBLISHER_PRIVATE_KEY`, `ENS_EDITOR_PRIVATE_KEY`), supplied through a secrets file outside git in a service that has no LLM or tool-call surface. They are separate keys; the service refuses to start if they are the same account. Where that secrets file lives on the server is deployment wiring, not decided here.
- **O10:** a new record `mergit.operator` holds the current Base operator of the agent. The publisher key writes it (chain-derived, like the reputation mirror). The web app compares it with `Identity.operatorOf(N)`; a difference shows "owner changed, not verified". Mergit learns of a transfer because every publish pass re-reads `operatorOf` for each configured agent. This adds one grant (publisher also holds `mergit.operator`) to the one-shot from #67.
- **Counting rule:** only tier 0 outcomes count (invariant 6). A task counts **once**: if both a source 0 (audit) and a source 1 (challenge ruling) outcome exist, the higher source wins and its `success` is used. `auditedStaked` is the number of counted tasks, `verifiedStaked` those that succeeded.
- **Signatures:** edit requests are signed with EIP-191 by an externally owned account. Contract wallets (EIP-1271) are not supported in v0.

## Global Constraints

- Work on `main`; no branches or PRs. **Never run git write commands**; print commit commands for the user, with no `Co-Authored-By` trailer.
- All code under `ens/` (outside every CI path filter: no CI, no deploy).
- Mainnet is **never written by Claude**; fork tests use anvil test accounts and impersonation only. Keys come from the environment only in the service; no key is ever printed, logged or put in an error message (check `cause` chains too).
- RPC URLs come from the environment (`ENS_MAINNET_RPC`, `BASE_SEPOLIA_RPC`); tests default Base Sepolia to `https://sepolia.base.org` and skip when `ENS_MAINNET_RPC` is unset.
- **`eth_getLogs` on the public Base Sepolia RPC is limited to a 200-block range** (measured 2026-11-06). The default chunk size is 200 and is configurable.
- `ReputationAnchor` `0xf9DBfF75887361A67269765DA6F8732b233Fda76`, `Identity` `0x72eAc041Ee897fF0385022639452fE08Dcd4B7D6`, chain 84532, deploy block 51760675. Event: `OutcomeRecorded(bytes32 indexed taskId, uint256 indexed agentId, bytes32 category, bool success, uint256 costMicros, uint8 tier, uint8 source)`. `category` is `keccak256(label)` and cannot be decoded: show the label only for labels in the configured known list, otherwise the `0x` hash. The validator `0xb41263A86d0EB428Dd1895f7110060Da7EC89F55` holds `RECORDER_ROLE` (used by fork tests via impersonation).
- Role policy: publisher holds `mergit.reputation` and `mergit.operator`; editor holds `agent-context` and `agent-endpoint[web]`; operators hold nothing.
- `mergit.reputation` JSON is exactly the HLD 6.3 shape; keys sorted so an unchanged state serialises to the identical string.

## Review Focus

1. **Same task recorded twice** (audit verdict, then a challenge ruling that overturns it): counted once, the ruling wins, never double counted. (Task 1)
2. **Tier 1 / faucet outcomes** and a state where nothing counted changed: never counted, and a publish pass sends **no transaction**. (Tasks 1, 4)
3. **Forged, replayed or out-of-policy edit requests:** expired, nonce reused, signature by someone else, signature over a different agent or value, key outside the allowlist (`mergit.reputation`, `mergit.operator`, `agent-registration[...]`), non-https endpoint, control characters, oversize value. (Task 3)
4. **Agent transferred on Base:** the previous owner's edit is refused immediately (ownership is read at request time), and the next publish pass updates `mergit.operator`; an unchanged state writes nothing. (Tasks 3, 4)
5. **RPC range limit and failures:** a 200-block limit is handled by chunking; a failing chunk fails the whole pass with nothing written; the service refuses to start with the same key for editor and publisher. (Tasks 2, 4, 5)

### Task 4: Publish pass

**Files:** Create `ens/src/publisher.ts`; Test `ens/test/publisher.test.ts`

**Interfaces:**
- Consumes: Tasks 1 to 3, `fetchOutcomes`, the resolver ABI, `dnsName`, `ensNameOf`.
- Produces: `type PublisherConfig = { chain: { chainId: number; identity: Address; anchor: Address }; resolver: Address; agents: { label: string; agentId: number }[]; knownCategories: string[]; fromBlock: bigint; chunk?: bigint }`; `type PassResult = { asOfBlock: bigint; changed: { label: string; key: string }[]; hash: Hex | null }`; `publishPass(ctx: { base: PublicClient; ens: PublicClient; wallet: WalletClient }, cfg: PublisherConfig): Promise<PassResult>`. It reads outcomes up to the current Base head, folds them, reads `operatorOf` for each configured agent, builds the desired `mergit.reputation` and `mergit.operator` for each agent that has counted outcomes or an operator, reads what the resolver holds (through `resolve`), and sends **one `multicall` of `setText` calls for only the records that differ**. If nothing differs it sends nothing and returns `hash: null`. `asOfBlock` in the written JSON is the Base head used. Records for agents with no counted outcomes keep no `mergit.reputation` write (the record is absent, not zero) but do get `mergit.operator`.

- [ ] **Step 1: Write failing fork tests** (two anvil forks: mainnet for ENS, Base Sepolia for outcomes and `Identity`; skipped without `ENS_MAINNET_RPC`; use the #67 harness to deploy a resolver with the publisher holding both keys): (a) after the validator records two tier 0 outcomes (one success, one failure) for an agent registered on the Base fork, a pass writes `mergit.reputation` that parses to `auditedStaked 2`, `verifiedStaked 1` with the right `asOfBlock`, and `mergit.operator` equal to `operatorOf`; (b) a second pass immediately afterwards returns `hash: null` and the ENS fork's block number has not moved; (c) a tier 1 outcome alone changes nothing (no transaction); (d) a new tier 0 outcome produces a pass that changes only `mergit.reputation`; (e) after the NFT is transferred on the Base fork (impersonate the old operator, `transferFrom`), the next pass changes only `mergit.operator` to the new owner; (f) a pass whose Base `getLogs` fails writes nothing; (g) the publisher key cannot be used for any other key (a pass never writes `agent-context` even if asked: covered by the role test, assert the sent calls contain only the two keys).
- [ ] **Step 2: Run and see it fail**, **Step 3: implement**, **Step 4: run and see it pass.**
