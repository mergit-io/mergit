# ENS Gate (M0, M1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer, with evidence, the questions that decide whether the ENS integration is feasible: who owns `mergit.eth` and in which ENS generation, whether there is money for gas, whether roles can be limited the way the permission model needs, and what the writes really cost.

**Architecture:** A small read-only TypeScript package, `ens/`, that (a) prints a gate report from mainnet and (b) runs role and gas tests against a local mainnet fork (anvil) using the real ENSv2 contracts that are already deployed on mainnet. Nothing here writes to mainnet. The results are written back into the HLD.

**Tech Stack:** Node 24 (runs `.ts` directly, so use only erasable TypeScript syntax: no enums, no parameter properties), viem 2.57 or later (the frontend already pins `^2.57.12`), `node:test`, anvil and cast (installed).

**Spec:** `docs/HLD-ens-integration.md` (sections 4, 7, 9, 11, 12) and GitHub issue #66. Contract addresses come from <https://docs.ens.domains/learn/deployments>; role behaviour from <https://docs.ens.domains/ensv2/permissioned-resolver>, `/ensv2/subnames` and `/ensv2/verifiable-factory`.

## Global Constraints

- Work on `main`. Do not create branches or PRs. **Never run git write commands**: where a step says "Commit", print the command for the user to run, with no `Co-Authored-By` trailer.
- All ENS code lives in a new top-level `ens/` directory. It is outside every workflow's `paths:` filter, so pushing it triggers no CI and no deploy. Do not add it to a workflow.
- Mainnet is **read-only** in this plan. No private key for `mergit.eth` is ever read, requested or stored. Fork tests use anvil's built-in test accounts and `anvil_impersonateAccount`.
- RPC URLs come from the environment (`ENS_MAINNET_RPC`), never from code or git. Tests that need it are **skipped**, not failed, when it is unset.
- viem 2.35.0 or later; ENSjs 5.2.5 or later is only needed for ENSv2 writes in later issues, not here (calls go straight to the contracts with viem).
- Mainnet ENSv2 addresses, copied from the deployments table (checked 2026-11-06, not yet verified on chain): `PermissionedResolverImpl 0x565b0f456a04ac9b48758190e90030623cff57c5`, `VerifiableFactory 0x77510ba162dfea3d8989e3f0928a691b345730d2`, `ETHRegistry 0xf60aba43e1f7f3dab1186ff03b561401c9df85e2`, `UniversalResolverV2 0x06fdd07f007adac667177b46ab2eb9a75132cfd5`.
- Facts the docs state and this plan must **test, not assume**: roles are per resolver instance and not per name; `grantSetterRoles(setter, account)` takes ABI-encoded `setText` calldata and scopes the role to that key; the text-key resource is `keccak256(bytes(key))`; `ROLE_SET_TEXT = 1 << 4`; a write without the role reverts with `EACUnauthorizedAccountRoles`; `grantRoles()` always reverts with `EACCannotGrantRoles`; the proxy comes from `VerifiableFactory.deployProxy(address implementation, uint256 salt, bytes data)` with `data = initialize((address account, uint256 roleBitmap)[] grants, bytes[] calls)`.
- Code licence GPL-3.0 (repository default).
- Executing this plan from a Claude Code session: the sandbox blocks mainnet RPC hosts and anvil's fork connection. The user must allow the host, or run the live steps themselves with `!`.

## Review Focus

1. **`mergit.eth` lives only in ENSv1.** The docs say mainnet registrations still go through ENSv1 until the launch completes. Expected: the report says `generation: "v1"` or `"unknown"` in plain words and the plan stops with that finding. It must never print a v2 owner it did not read. (Task 2)
2. **RPC down, rate-limited or returning an error mid-report.** Expected: a non-zero exit and a message naming the failed read. Never a half-filled "OK" report. (Task 2)
3. **Name expired or inside a grace period.** Expected: expiry date printed with a warning, not silently omitted. (Task 2)
4. **Resolved address is not the owner.** The HLD already records that the address `mergit.eth` points at held 0 ETH and 0 USDC. Expected: balances are reported separately for the resolved address and for the owner, never merged into one "team balance". (Task 2)
5. **Role leakage by similar key.** A role for `mergit.reputation` must not allow `mergit.reputation2`, `Mergit.reputation`, or an empty key; a key containing brackets such as `agent-endpoint[web]` must scope exactly. Expected: each of those reverts. (Task 4)

(Also pinned in Task 2: a stale Chainlink ETH/USD reading is flagged, not used silently.)

### Task 2: M0 gate report (read-only mainnet)

**Files:**
- Create: `ens/src/gate.ts`, `ens/src/gate-cli.ts`
- Test: `ens/test/gate.test.ts`

**Interfaces:**
- Consumes: `MAINNET` and the registry ABI from Task 1.
- Produces:
  - `export type GateReport = { name: string; generation: "v2" | "v1" | "unknown"; resolvedAddress: Address | null; owner: Address | null; expiresAt: Date | null; inGracePeriod: boolean | null; balances: { resolvedAddress: { ethWei: bigint; usdc: bigint } | null; owner: { ethWei: bigint; usdc: bigint } | null }; gasPriceWei: bigint; ethUsd: { price: number; updatedAt: Date; stale: boolean }; findings: string[] }`
  - `export async function readGate(client: GateClient, name: string): Promise<GateReport>` where `GateClient` is the minimal interface of viem's public client that the function uses (so the test can pass a stub).
  - `export function estimateCostUsd(gasUnits: bigint, gasPriceWei: bigint, ethUsd: number): number`

- [ ] **Step 1: Write failing tests** in `ens/test/gate.test.ts` with a stub `GateClient`:
  - `estimateCostUsd(350_000n, 125_000_000n, 2416)` equals `350000 * 0.125e-9 * 2416` to 6 decimals (about $0.1057).
  - `readGate` with a stub where the v2 registry has no entry and a v1 entry exists returns `generation: "v1"` and a finding containing the words `ENSv1`.
  - A stub where any read throws makes `readGate` reject with a message containing the name of the failed read (Review Focus 2).
  - A stub whose registry expiry is in the past, or within the grace period, sets `inGracePeriod` or adds a finding containing `expired` (Review Focus 3).
  - A stub where `resolvedAddress !== owner` returns two separate balance entries and a finding stating they differ (Review Focus 4).
  - A stub whose Chainlink `updatedAt` is more than 3 hours old sets `ethUsd.stale = true` and adds a finding (stale feed).
- [ ] **Step 2: Run to see failure:** `node --test test/gate.test.ts` fails with module not found.
- [ ] **Step 3: Implement `readGate`.** Order of reads: resolve the name through `UniversalResolverV2` (viem `getEnsAddress` with the v2 resolver address set explicitly); read ownership and expiry from `ETHRegistry` for the label (`mergit`); only if v2 has nothing, check v1 (BaseRegistrar `ownerOf(uint256(keccak256("mergit")))` at `0x57f1887a8BF19b14fC0dF6Fd9B2acc9Af147eA85`; the NameWrapper may hold the token, so if the owner is the NameWrapper (`0xD4416b13d2b3a9aBae7AcD5D6C2BbDBE25686401`) also read `ownerOf(uint256(namehash("mergit.eth")))` there) and set `generation: "v1"`; if neither, `"unknown"`. Balances: ETH via `getBalance`; USDC via `balanceOf` on mainnet USDC (`0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48`, 6 decimals). ETH/USD from the Chainlink aggregator `0x5f4eC3Df9cbd43714FE2740f5E3616155c5b8419` (`latestRoundData`, 8 decimals). Wrap each read so a failure rethrows as `new Error("gate: <which read> failed: <cause>")`. Do not catch and continue.
- [ ] **Step 4: Implement `ens/src/gate-cli.ts`:** reads `ENS_MAINNET_RPC`, calls `readGate(client, "mergit.eth")`, prints the report as JSON (bigints as strings) followed by a short markdown summary and the `findings` list; exits 1 if the RPC variable is missing or a read failed.
- [ ] **Step 5: Run tests and see them pass:** `node --test test/gate.test.ts`.
- [ ] **Step 6: Commit.** Print: `git add ens/src/gate.ts ens/src/gate-cli.ts ens/test/gate.test.ts && git commit -m "ens: M0 gate report (owner, generation, expiry, balances, gas cost)"`

**Interfaces:**
- Consumes: `MAINNET`, `verifiableFactoryAbi`, `permissionedResolverAbi` from Task 1.
- Produces:
  - `export async function startFork(): Promise<{ rpcUrl: string; stop(): Promise<void> }>`: spawns `anvil --fork-url $ENS_MAINNET_RPC --port <free port> --silent` and waits until `eth_chainId` answers; `stop` kills the process.
  - `export async function deployResolver(client: WalletClient, owner: Address): Promise<Address>`: calls `VerifiableFactory.deployProxy(MAINNET.permissionedResolverImpl, salt, initData)` with `salt` and `initData` as the docs define, grants the owner every role (`0x1111...1111` bitmap as in the docs example), parses `ProxyDeployed`, and returns the proxy address. Salt must be unique per call so tests can deploy several resolvers.

  - `export function node(name: string): Hex`: viem `namehash`.

- [ ] **Step 2: Run it and see it fail** (helpers not defined). Needs `ENS_MAINNET_RPC` and permission to reach it.
- [ ] **Step 3: Implement `startFork`, `deployResolver`, `ACCOUNTS`, `node`.** If the `setText` signature in the collected ABI differs from `(bytes32,string,string)`, use the ABI's signature and note it in the file header.

### Task 4: M1 role spike, the tests that decide O1 and O9

**Files:**
- Test: `ens/test/roles.test.ts`

**Interfaces:**
- Consumes: `startFork`, `deployResolver`, `ACCOUNTS`, `node` from Task 3; the resolver ABI.
- Produces: pass or fail results that Task 6 writes into the HLD. No code interface.

Setup shared by every test: one fork per file, one resolver per test (so grants do not leak). `admin` owns the resolver. Two names are used: `coder-0.mergit.eth` (Alice's agent) and `coder-1.mergit.eth` (Bob's). Helper `setterRole(key)` builds the `setText(node(any), key, "")` calldata the docs describe, and `grantKey(resolver, account, key)` calls `grantSetterRoles(calldata, account)` as `admin`.

- [ ] **Step 1: Write the failing tests**, each named so the HLD can quote it:
  1. `publisher can write mergit.reputation on every name`: grant `publisher` the key `mergit.reputation`; it writes that key for both names; both read back.
  2. `publisher cannot write any other key`: the same account writing `agent-endpoint[web]` or `agent-context` reverts with `EACUnauthorizedAccountRoles`.
  3. `an account with no role cannot write mergit.reputation` (the HLD's "operator write reverts" test): `alice` writing `mergit.reputation` on her own name reverts.
  4. `role does not leak to a similar key` (Review Focus 5): with the `mergit.reputation` role granted, writing `mergit.reputation2`, `Mergit.reputation` and the empty key `""` each revert.
  5. `bracketed key scopes exactly`: a role for `agent-endpoint[web]` allows that key and rejects `agent-endpoint[api]` and `agent-endpoint`.
  6. `L1: a key role is per resolver, not per name`: grant `alice` the key `agent-endpoint[web]`; assert she **can** write it for `coder-1.mergit.eth` (Bob's name). This test passing means L1 is real; its name and a comment say so.
  7. `option (a): operators hold no role, Mergit's key writes`: with no grant to `alice` or `bob`, both writing `agent-endpoint[web]` on their own names revert; granting the `mergit` account the key lets it write both names.
  8. `grantRoles is disabled`: calling `grantRoles(...)` reverts with `EACCannotGrantRoles` (confirms the docs, so no later code relies on it).
- [ ] **Step 2: Run them (`node --test test/roles.test.ts`) and see what fails.** Failures here are findings, not bugs to hide: if any docs-stated behaviour does not hold on the deployed contracts, **stop and report which one**, because the permission model in HLD section 7 depends on it. Test 6 is expected to pass.
- [ ] **Step 3: Adjust only the tests' setup** (encoding, argument order) until every failure is a real contract behaviour and not a harness mistake. Do not weaken an assertion to make it pass.
- [ ] **Step 4: Run again and keep the full output** (`node --test --test-reporter=spec test/roles.test.ts > ens/roles-report.txt`). This file is the evidence for the HLD.
- [ ] **Step 5: Commit.** Print: `git add ens/test/roles.test.ts ens/roles-report.txt && git commit -m "ens: M1 role spike, key-scoped roles and the L1 check"`
